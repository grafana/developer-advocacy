## Summary

The show is titled "Agent Observability Deep Dive Demo | Grafana Cloud" and was published on July 31, 2026. The speakers discussed the new Grafana AI Observability platform, which is designed to monitor the performance and behavior of AI agents. Key features highlighted include the ability to instrument agents quickly, analyze performance metrics such as error rates and latency, and evaluate agent behavior through online evaluations. The platform also allows users to set alerts and gain insights into agent usage trends, ultimately helping developers improve their AI agents' effectiveness and security. 

Topics: Grafana AI Observability, agent performance monitoring, online evaluations, performance metrics, alerting system.

[music] 

Over the past year at Grafana Labs, we've built agents. We needed a way to understand how they are performing, including the costs associated with them, their error rate, time to the first token, and their overall behavior. We wanted to ensure they are not hallucinating and that they are helpful for our users. That's why we built **Grafana AI Observability**. It connects our experience in building agents with our experience in building observability systems. This has helped us answer our questions, and we believe there are many developers out there currently creating agents who can benefit from Grafana AI Observability as well.

[music] 

The first step we need to take is to instrument our agent. You can click on "Start Setup," which will take you to a page where you can access our coding agent skills that will help you instrument your app within minutes. If you are using **Cursor**, **Cloud Coder**, or **Copilot**, you will be able to instrument your agent app quickly and start sending telemetry to Grafana AI Observability. We already did that with our assistant, so now we can look at the data and review our assistant.

[music] 

The analytics page provides an overview of how your agents are performing over time. You can gain insights into the error rate, time to the first token, latency, and very important metrics such as the costs associated with each of your agents. If you would like to drill down into a specific view or debug a specific problem, we have created dedicated views to see performance, errors, token usage, or tool usage over time. You can also break down the data by model or even your LLM provider.

[music] 

With all of these metrics, we learn about the performance of our agents. However, it is also very important to understand their behavior. Are they not hallucinating? Are they helpful? Are they responding securely? This is where online evaluation comes in. With online evaluations, we can determine whether agents are behaving correctly, which can mean different things for different agents. With evaluations, you can decide what correct behavior means to you.

[music] 

The first step is to decide what we care about—what's the correct behavior in our case? Here, I'm going to set up an **LLM judge**. We will use another LLM to judge our LLM, our AI, to verify whether our assistant grounds its answers in real data and does not hallucinate. The second evaluator I’m going to choose is more security-oriented; this one will evaluate whether users are trying to use prompt injection on our agent. In this case, we can detect these attempts and verify whether the assistant responded securely. The last evaluator I’m going to pick is a simple heuristic one, where we check the length of the response. Here, we want to ensure that the assistant is not showing a wall of text to our users and that it is nicely summarizing data.

You can create a new evaluator if you would like to observe something else, either from scratch or by using one of the templates we provide. Now that we have our evaluators, they will run on real conversations where they will evaluate and score them, letting us know whether they passed or failed. The first step we need to do is decide which conversation it will be run on.

[music] 

Here, I am picking the **Grafana Assistant** agent. You can pick one agent or multiple agents and adjust the sample rate. In this case, I'm going to keep it at 50%. You can keep the sample rate lower if you have high-traffic agents. If your agents are generating thousands of responses every minute, you probably want a lower rate than if it's a new agent with low traffic. In this case, you could go as high as 100%.

[music] 

We are going to give our evaluation rule a name. We also created an easy way for you to set up alerts, which is basically a one-click, two-click integration that works with **Grafana** alerting. In this case, if the evaluation pass rate falls below 70%, we will get notified. Now, let's start scoring. Looking at the results, we now have a measurable way to evaluate the behavior of our agents. We can review it over time and monitor trends. We have set up alerts, so we will be notified if something goes wrong.

In this case, we can drill down into specific conversations that have failed evaluation. As you can see here, we have a list of conversations with the lowest pass rate over the last 24 hours. Let's take a look at one of these conversations. We are now in the conversation view, where we can see metadata about the conversation, the actual messages exchanged between the user and the agent, and the tools that were called. We can also see the model and tokens used for this generation.

We were talking about evaluations, so we can see all of the evaluations that were run on this conversation, including the failing ones. In this case, we also see detailed information on why this evaluation failed. For example, while the user asked about failing alerts in the last 30 days, the assistant decided to navigate to the alerting page but did not directly answer the question. We would want to ensure that the assistant also answers that question. We could take this example, turn it into a test case, and bring it into our development flow to fix it in future iterations of the assistant, preventing this issue from happening again.

One of the most powerful features we have is **Agent Insights**. With Agent Insights, you can analyze your agent, including your system prompt and tools, based on real conversations that have occurred. I'm going to click "Reanalyze" and pick conversations from the last three days. Here, we will get strengths—concrete examples and insights into what works well in our prompt—and on the other side, we will see weaknesses and areas for improvement.

[music] 

As you can see here, we get insights on how well we are optimizing brevity guidance. It indicates that we have an overly complex nested XML structure. In future iterations, we could work on that and improve it. Additionally, I would like to highlight that users are using agents differently over time. This helps ensure that your agent works well for the current use cases of your users and how they are using it at the moment.

The tools page gives you an overview of all the tools in your agents. You can even filter down for a specific agent that you care about. In this case, I'm filtering for **Grafana Assistant**. Here, we can see all of the tools that were used in the Assistant in the last 24 hours. We can sort them by execution percentage, error rate, or latency. I can even drill down into a specific tool to get more detailed analytics on usage trends, error trends, and which agents have been using this tool. In this case, it was used only by Grafana Assistant tools, but we sometimes have tools that are used across multiple agents. You can see all of that in this view. We can even drill down into conversations where this tool was used, find the tool, and get more insights on the input and output of this tool.

This is **Grafana AI Observability**. This is how we are observing our agents in a truly useful way. If you are building agents and are interested in AI observability, give it a try on **Grafana Cloud**.

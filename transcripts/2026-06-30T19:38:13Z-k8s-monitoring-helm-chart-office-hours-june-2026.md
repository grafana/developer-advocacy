**Kubernetes Monitoring Helm Chart Updates**

For the 4.1 release, we've had this version out for a little while. Since the last office hours, the biggest changes have occurred in three different patch releases. You can look at the release notes to see all of the different updates, but here’s a summary of the most significant ones:

- **Cost Metrics Features**: We added further improvements to how we handle configuration. The way that OpenCost, which is the component we deploy to get cost metrics, works is that for certain features it requires a config file, while for others it does not. We are trying to deploy this in a way that is the most portable across different platforms, specifically important for the GKE platform where an API signing key is needed. We believe we have nailed down the most flexible and portable way of deploying OpenCost without requiring a lot of manual intervention.

- **OTLP Destination**: We have added timeouts to the OTLP destination. If you want to further tune how your OTLP destination works, there is now a timeout feature available.

- **Helm Chart Validators**: We made various improvements to the validators inside the Helm charts. This includes smarter ways of finding dependencies if you're using features like the cluster metric feature with kube-state-metrics and node-exporter already on a cluster. We are guiding users through those dependencies and improving platform validation and verification.

- **Dependencies**: We always include the latest dependencies for our Helm charts, including node-exporter, kube-state-metrics, windows-exporter, OpenCost, Kepler, Grafana Beyla, and Grafana Alloy. We strive to keep these as up-to-date as possible.

- **Upcoming Release**: Later today, we will probably be releasing 4.1.7. The most exciting feature coming with that is Helm chart signing and verification. The Helm charts we publish to our Helm chart repository will be signed by a GPG key, allowing you to verify them for better supply chain security. We are incorporating a lot of this into our Helm chart building, so the dependencies we pull will also be checked and verified.

**KSM Helm Chart 4.2**

I've been discussing the upcoming feature release for KSM Helm Chart 4.2 for a while. It has slowed down this past week due to our work on the Helm chart signing and verification. However, we are close to finishing up all of the planned features. 

The last feature I need to merge in is the EC2 enrichment. This means that if you are running on an EKS cluster with EC2 nodes, we can pull tags from those EC2 nodes and add them as labels or attributes to your metrics, logs, traces, and profiles. I recently merged in the Kubernetes enrichment, which has a similar function regarding namespace labels.

**Deprecation Notice**

On June 1st, we officially deprecated versions 1 and 2. If you are running on either of those versions, I highly recommend upgrading to version 3 or 4. Version 4 is receiving all the new features and will have faster turnaround for feature releases. We will deprecate version 3 at some point, but there is no date for that yet. If I had to guess, it wouldn't be until later in the fall, but that is not a guarantee.

Please plan to upgrade to version 3 or 4. Both V3 and V4 will have changes to the values file. If you're coming from V1, we have a migration utility to assist you. If you're already on version 2, transitioning to version 3 should be straightforward with minimal changes to the values file. However, moving to V4 will require some changes, but it should be fairly simple. Please check the values file or the migration utility and refer to our documentation for details on what needs to be changed for migration.
